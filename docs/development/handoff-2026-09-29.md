# Buildlog handoff — 29 September 2026

This is the restart point for the next working session. The application is currently usable as a local browser demo without Supabase.

## Product direction now established

- Buildlog is a workshop record for physical projects, not a bookkeeping product.
- A project can consist entirely of its story, photographs and workshop logs.
- Parts/BOM and cost tracking are separate optional capabilities.
- The visual language is a workshop dashboard, master project record and handwritten/printed work order rather than a marketing site.
- The story of the object is the project anchor: how it started, why the build exists and what is known about the object.
- Themes belong to individual projects and should reflect the object.
- Project access will eventually have Owner, Contributor and Reader roles. Exact-email recognition and invitations are specified, but not connected yet.

The detailed accepted decisions remain in `docs/architecture/product-decisions-v0.4.md`.

## Completed

### Foundation

- Nuxt 4 application structure, shared layout, navigation and responsive styling.
- Supabase-oriented domain types and client composables.
- Initial Postgres schema, relational constraints, RLS policies, Storage design, story migration and seed data.
- Local demo mode stored in the browser, so the complete interface can be developed without a Supabase project.
- Two demo bicycle projects with real source photography: Peugeot and Gios Torino.

### Workshop dashboard

- Homepage rebuilt as a functional workshop dashboard instead of a marketing landing page.
- Projects grouped into active work and completed work.
- Aggregate workshop statistics.
- Prominent Quick Workshop Log action.

### Project presentation

- Object-led project header with project-specific imagery and colour theme.
- Story section with three narrative anchors.
- Build phases and current status.
- Workshop-log timeline and project statistics.
- Optional materials/BOM presentation; costs stay hidden when disabled.
- Owner-only Edit project entry point.

### Project creation and editing

- Creating and editing now render the same shared `ProjectRecordForm` component.
- Both flows contain exactly the same functional controls:
  - title, subtitle, description and address/slug;
  - large cover image;
  - project story;
  - add, rename, reorder and archive/restore build phases;
  - current phase;
  - theme presets and manual colour/heading choices;
  - public/private visibility;
  - optional BOM, optional costs and reporting currency;
  - reserved collaboration section.
- Create mode begins with sensible bicycle-restoration defaults; edit mode fills the same form with existing data.
- Local demo persistence supports project updates, phase changes, theme changes and cover replacement.
- Live-mode save and image-upload paths are implemented against the proposed Supabase schema, but are not yet exercised against a real project.

### Workshop logs and materials

- New workshop-log page uses a playful old work-order/paper treatment.
- Log entry supports work date, duration, phase, narrative, findings/decisions and photographs.
- Existing logs have a view and edit flow.
- BOM/material use can be attached to workshop work when enabled.
- A project materials page and local demo material state are present.
